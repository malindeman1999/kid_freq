Math Used by the Nonlinear Resonator Fitter

This note explains the nonlinear resonator model used by the new GUI resonance fitter, how it maps onto the paper Operation of a titanium nitride superconducting microresonator detector in the nonlinear regime, and why the fitted frequency parameter is the low-power resonance frequency \(f_{r,0}\), not the power-shifted resonance frequency \(f_r\).

Code locations used here: citkid-main/citkid/res/funcs.py, citkid-main/citkid/res/fitter.py, and analysis_gui_support/gui_mixins/resonance_selection_mixin.py.

Paper Model

In the linear resonator model, the paper writes the forward transmission as

\[ S_{21} = 1 - {Q_r \over Q_c}{1 \over 1 + 2jQ_r x}, \]

with detuning

\[ x = {\omega_g - \omega_r \over \omega_r}. \]

The paper then introduces nonlinear kinetic inductance. The resonance frequency shifts from its low-power value:

\[ \omega_r = \omega_{r,0} + \delta \omega_r. \]

For the soft-spring kinetic-inductance nonlinearity in the paper,

\[ \delta x = {\delta \omega_r \over \omega_{r,0}} = -{E \over E_*}. \]

The sign is physically important: for positive stored energy and positive nonlinearity scale, the resonance shifts downward.

The paper defines the low-power detuning

\[ x_0 = {\omega_g - \omega_{r,0} \over \omega_{r,0}}, \]

and dimensionless linewidth-scaled variables

\[ y = Q_r x, \qquad y_0 = Q_r x_0. \]

The nonlinear equation appears as

\[ y = y_0 + {a \over 1 + 4y^2}. \]

Rearranged into the form solved by the code, this is

\[ y_0 = y - {a \over 1 + 4y^2}. \]

Code Model

The core code in citkid.res.funcs.nonlinear_iq computes 

deltaf = f - fr
y0 = Qr * deltaf / fr
y = get_y(y0, a, downward)
s21_readout = (i0 + 1.j * q0) * exp(-2.j * pi * deltaf * tau)
s21_res = 1 - (amp / cos(phi)) * exp(1.j * phi) / (1 + 2.j * y)
z = s21_readout * s21_res

Written mathematically, the fitted model is

\[ z(f) = (i_0 + jq_0)e^{-2\pi j(f-f_{r,0})\tau} \left[ 1 - {A \over \cos\phi} {e^{j\phi} \over 1 + 2jy} \right], \]

where \(A\) is the fitted amp parameter, documented as \(Q_r/Q_c\), and \(y\) is the selected real root of the nonlinear cubic.

The Actual Cubic Solved by get_y

The code calls 

cardan(4.0, -4.0 * y0, 1.0, -(y0 + a), largest)

so the polynomial being solved is

\[ 4y^3 - 4y_0y^2 + y - y_0 - a = 0. \]

This is equivalent to

\[ y_0 = y - {a \over 1 + 4y^2}. \]

That matches the paper equation after rearranging \(y = y_0 + a/(1 + 4y^2)\).

Proof that the Fit Returns \(f_{r,0}\), Not \(f_r\)

The proof is direct from the code definition of \(y_0\):

\[ y_0 = Q_r {f - f_r^{\mathrm{code}} \over f_r^{\mathrm{code}}}. \]

In the paper,

\[ y_0 = Q_r x_0 = Q_r {\omega_g - \omega_{r,0} \over \omega_{r,0}}. \]

Identifying \(f\) with the generator frequency and using \(f=\omega/(2\pi)\), the code's fitted fr parameter has to be the frequency used in the denominator of \(x_0\):

\[ f_r^{\mathrm{code}} = f_{r,0}. \]

The code does not fit a separate power-shifted \(f_r\). Instead, it fits \(f_{r,0}\), \(Q_r\), and \(a\), then solves the nonlinear detuning equation to generate the shifted response branch.

The GUI therefore labels the input field as fr0 (GHz). The fitted payload stores both fr0_hz and the older compatibility key fr_hz; both refer to the fitted low-power resonance frequency.

Derived Shift Used by the GUI

The shifted resonance condition in the paper is \(x=0\), equivalently \(y=0\). Substitute \(y=0\) into the code/paper nonlinear equation:

\[ y_0 = y - {a \over 1 + 4y^2} \quad\Longrightarrow\quad y_0 = -a. \]

Since

\[ y_0 = Q_r {f_{\mathrm{true}} - f_{r,0} \over f_{r,0}}, \]

the model-predicted shifted resonance frequency is

\[ f_{\mathrm{true}} = f_{r,0}\left(1 - {a \over Q_r}\right). \]

The reported shift is therefore

\[ \Delta f_r = f_{\mathrm{true}} - f_{r,0} = -{f_{r,0}a \over Q_r}. \]

This is what the GUI reports in the output-only fields:

GUI output Definition
true fr (GHz) \(f_{\mathrm{true}} = f_{r,0} + \Delta f_r\)
delta fr (Hz) \(\Delta f_r = -f_{r,0}a/Q_r\)

Positive \(a\) gives a negative \(\Delta f_r\), so the true shifted resonance marker should appear to the left of the \(f_{r,0}\) marker.

What the Fitter Optimizes

The fitter returns eight optimized parameters:

\[ p = \left[ f_{r,0}, Q_r, A, \phi, a, i_0, q_0, \tau \right]. \]

The fit stacks real and imaginary residuals:

\[ r = \begin{bmatrix} \operatorname{Re}(z_{\mathrm{model}} - z_{\mathrm{data}}) \\ \operatorname{Im}(z_{\mathrm{model}} - z_{\mathrm{data}}) \end{bmatrix}. \]

In the GUI, the data passed to the fitter are the raw complex S21 samples visible in the selected plot window. If every parameter field is filled, the fields are used as the initial guess. If any field is empty, the GUI calls guess_p0_nonlinear_iq on the visible window and uses that guess.

Differences and Caveats

1. Code comments do not match the implemented equation

The comments/docstrings in citkid.res.funcs.py say:

\[ y_0 = y + {a \over 1+y^2}. \]

That is not the polynomial actually solved. The implementation solves:

\[ y_0 = y - {a \over 1+4y^2}. \]

The implementation matches the paper equation after rearrangement; the comment has both the wrong sign and a missing factor of 4.

2. The paper's basic transfer function is idealized

The paper's Eq. 1 is

\[ S_{21} = 1 - {Q_r \over Q_c}{1 \over 1+2jQ_rx}. \]

The code includes additional practical fit terms:

  • \(i_0 + jq_0\): complex gain/offset scale,
  • \(\tau\): cable/electrical delay term,
  • \(\phi\): impedance mismatch rotation,
  • \(A/\cos\phi\): coupling-depth parameterization with \(A=\mathrm{amp}\).

3. The fitter docstring assumes gain and phase are removed

fit_nonlinear_iq says the system gain and phase are assumed to be removed before fitting, and that \(i_0\), \(q_0\), and \(\tau\) are only fine-tuning terms. The GUI currently fits raw S21 directly. That can still work because the model has \(i_0\), \(q_0\), \(\tau\), and \(\phi\), but it is a looser fit problem than the docstring's preferred calibrated use case.

4. The code's fr name is ambiguous

The code parameter is named fr, but mathematically it maps to \(f_{r,0}\). The GUI now labels it fr0 to avoid confusing it with the power-shifted resonance \(f_{\mathrm{true}}\).

5. A scaling comment in nonlinear_iq_for_fitter is typo-prone

The comment says the fitter input is scaled as fr X 100^6. The implementation actually multiplies by 100e-6 before fitting and divides by 100e-6 inside nonlinear_iq_for_fitter. The implementation is internally consistent; the comment is easy to misread.

Summary

  • The fitted frequency parameter is \(f_{r,0}\), the low-power resonance frequency.
  • The shifted resonance is derived, not independently fitted.
  • The GUI reports \(f_{\mathrm{true}} = f_{r,0}(1-a/Q_r)\).
  • The GUI reports \(\Delta f_r = -f_{r,0}a/Q_r\).
  • The implementation matches the paper's nonlinear equation, but the code comments describing that equation are wrong.
